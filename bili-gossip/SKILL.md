# 深度吃瓜

通过公开网页搜索生成可溯源、可降级的HTML报告，并聚合可公开访问的B站视频。

## 工作流

1. 识别用户输入中的人物名、事件名和关系词。只有一个明星姓名时，默认生成人物近况与关键前情复盘；出现两个姓名时，默认生成双方关系、公开互动与近期触发点复盘；出现三个及以上姓名时，围绕共同事件梳理核心当事人、回应者、关联者和背景人物，不把所有人机械地两两组合。姓名可由`&`、`和`、`与`、`×`、空格或顿号连接，不要求用户额外写“关系”或“复盘”。
2. 使用Agent自带的Web搜索分别检索“核心人物/事件”“最近为什么又被讨论”“官方回应”“事件日期/进展”。先识别引发用户兴趣的本轮话题触发点，再决定需要补充哪些前情；若没有可靠的近期触发点，按旧闻考古或人物背景复盘处理，不强行制造新进展。打开候选原文，不直接采用搜索结果摘要。
3. 按官方一手声明、权威媒体、正规门户的顺序收集事实；微博智搜、抖音求真卡、B站搜索仅作可用时的补充。为每个来源记录名称、原文URL和来源类型。
4. 普通事实节点至少需要两个不同域名的独立来源相互印证；官方机构、当事人或工作室的一手声明标记为`is_primary: true`后可单独作为节点。
5. 生成不超过6个、按日期正序排列的时间线节点，删除无法确认的说法。选点时优先解释本轮话题触发点，再补充与它关系最强的起点、转折和必要背景；不要按年份、固定时间窗口或新旧节点比例机械凑数。近期动态与当前话题无关时不为追新而塞入，近期说法缺乏可靠来源时也不强行纳入。从已确认时间线压缩生成不超过50字的省流版，先回答“最近为什么又被讨论”，再交代关键前情；不得用弹幕、评论或单个UP主观点代替事实。
6. 使用Web搜索追加`site:bilibili.com/video`检索，收集与当前事件直接相关的1至3条视频，以及同人物/同事件延展的2至3条视频。打开视频页核对真实`bvid`、标题、UP主、链接及可见播放量/时长，并优先记录公开页面中的封面URL。
7. 不生成观点阵营、弹幕原文或精确视频时间戳。公开视频只能作为整条视频入口；无法确认播放量或时长时保留警告，不声称已经满足内部准入门槛。
8. 按[产品规则](references/product-rules.md)和[报告数据契约](references/report-contract.md)组织JSON。将Agent生成的JSON写入文件。若视频卡缺少封面，先从B站公开视频页的`og:image`公开元数据补齐：

```bash
python scripts/enrich_public_video_metadata.py --input <report.json> --output <enriched-report.json>
```

检查命令输出的`warnings`。封面请求失败时保留空值并继续，不删除已合格的视频，也不使用登录态、Cookie或页面截图伪造封面。再运行公开Web版准备脚本：

```bash
python scripts/prepare_web_only.py --input <enriched-report.json> --output <web-only-report.json>
```

检查命令输出的`warnings`。被删除的事实或视频不得补写；若时间线为空，使用全局兜底。

9. 渲染公开Web版JSON：

```bash
python scripts/render_report.py --input <web-only-report.json>
```

10. 将脚本输出的HTML路径返回给用户。

## 检索预算

- 一份常规报告默认打开约8至15个不同网页：5至8个事实信源页、3至6个B站视频页；同一原文可支持多个时间线节点，不重复打开。
- 同一事实达到双信源要求后停止扩张检索；优先补齐缺少交叉验证的节点，不为增加网页数量重复搜索相同结论。
- 时间线最多使用6个节点，直接相关视频最多3条，延展视频最多3条。只有信源冲突、原文失效或关键事实缺口时才突破默认预算。
- 播放量、时长、封面等可通过公开元数据请求核对时，不额外打开浏览器页面。封面优先使用公开页`og:image`并转成`https`原图URL；请求失败时保留警告和封面占位，不无限重试。

## 豆包与元宝

- 默认不操作豆包或元宝，优先使用Agent自带Web搜索。
- 只有用户明确要求且浏览器已登录时，才可临时操作其网页；不得索取或保存账号密码、Cookie或验证码。
- 将豆包/元宝输出只作为检索线索，不作为最终信源。必须打开其引用的原始网页并按双信源规则重新验证。
- 页面要求登录、出现验证码或无法稳定读取时立即跳过，不影响主流程。

## 内容边界

- 将“已确认事实”“UP主观点”“评论/弹幕情绪”分别标注，不混写。
- 不使用“实锤、真相、故意、内幕”等超出证据的定性词。
- 不把搜索结果摘要本身当作最终证据；尽可能打开原文核对标题、日期和正文。
- 数据未达到门槛时直接隐藏模块。全局信息不足时使用运营兜底文案。
- 所有视频卡必须绑定真实`bvid`和B站视频链接。能从公开页面获取封面时必须写入`cover`并展示；获取失败时允许使用模板占位。公开Web版不展示精确时间戳。
- 观点阵营和弹幕模块必须隐藏，不能把新闻评论、搜索摘要或豆包/元宝结论伪装成B站内部数据。

## 安装口令

```text
请从 https://github.com/jiubanszd/bili-gossip-skill/tree/main/bili-gossip 安装 bili-gossip Skill。
```

报告页面默认展示并复制这条可直接发送给Agent的安装指令；如需分发其他仓库版本，可通过`BILI_SKILL_INSTALL_COMMAND`临时覆盖。
